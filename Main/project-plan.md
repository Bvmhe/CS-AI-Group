## B. Project Scope & Learning Goals

### Target Learner Profile

- **Education level:** Undergraduate students, particularly first- and second-year Computer Science or IT students.
- **Prior knowledge:** Basic understanding of computer architecture, programming fundamentals, and computer networks.
- **Technical proficiency:** Beginner to intermediate, with familiarity with basic computational concepts and logical problem-solving.

### Learning Goals

1. **Understand AI Hardware:** Identify the main hardware components used in AI systems (CPUs, GPUs, memory, sensors) and explain their functions.
2. **Understand AI Networks:** Explain how networks allow AI systems and devices to communicate, exchange data, and access information.
3. **Explore Behaviourist AI:** Understand how AI systems can learn and improve their behaviour through interactions, feedback, and rewards.
4. **Connect Theory to Real-Life Applications:** Recognize how hardware, networks, and behaviourist AI are applied in self-driving cars, smart devices, and robots.
5. **Develop Basic AI Knowledge:** Build a strong foundation for understanding more advanced AI concepts in the future.

### Content Outline

#### 01. AI Hardware Architecture
- Definition and fundamental concepts of AI hardware
- CPU vs GPU vs TPU: architecture and performance
- Parallel processing and AI acceleration
- Memory hierarchy and computational efficiency
- **Case study:** Apple Neural Engine (on-device AI). Investigate how iPhones use specialized neural processing hardware for facial recognition, image processing, and other AI features.

#### 02. Computer Networks & AI Infrastructure
- Network architecture and communication protocols
- TCP/IP and data transmission
- Cloud computing vs edge computing
- Network latency, bandwidth, and scalability
- **Case study:** Cloud-based AI service (5G networks and AI-powered network optimization)

#### 03. Behaviourist AI & Reinforcement Learning
- Definition and principles of Behaviourist AI
- Agent-environment interaction
- Reward systems and feedback mechanisms
- Exploration vs exploitation
- **Case study:** Robot dogs learning to walk and adapt

#### 04. AI Sensors & Intelligent Systems
- Types of sensors: cameras, LiDAR, and ultrasonic sensors
- Data acquisition and real-time processing
- Sensor fusion and environmental perception
- Integration of hardware and AI decision-making
- **Case study:** Tesla's autonomous driving technology

#### 05. AI System Integration & Optimization
- Hardware-software interaction
- Distributed AI systems
- Performance optimization and resource allocation
- Challenges in AI infrastructure: energy consumption, cost, and scalability
- **Case study:** Google TPU infrastructure

### Scope Boundaries

#### In Scope

- **AI Hardware Architecture:** CPU, GPU, TPU, parallel processing, memory hierarchy, computational efficiency.
- **Computer Networks & AI Infrastructure:** Network architecture, communication protocols, cloud computing, edge computing, latency, bandwidth.
- **Behaviourist AI & Reinforcement Learning:** Agent-environment interaction, reward mechanisms, feedback systems, exploration vs exploitation.
- **AI Sensors & Intelligent Systems:** Sensor technologies, data acquisition, real-time processing, sensor fusion.
- **AI System Integration & Optimization:** Hardware-software interaction, distributed AI systems, resource allocation, performance optimization.
- **Real-World Case Studies:** AI applications in autonomous vehicles, cloud-based AI services, and intelligent computing systems.

#### Out of Scope

- Advanced mathematical derivations of machine learning and reinforcement learning algorithms.
- Development and training of complex AI models from scratch.
- Low-level hardware engineering, semiconductor fabrication, and circuit design.
- Advanced network security, cryptography, and penetration testing.
- Large-scale AI infrastructure deployment and enterprise-level system administration.
- Advanced deep learning architectures and Big Data analytics.

### Project Boundaries

This project provides an intermediate-level understanding of the technical foundations of Artificial Intelligence, specifically hardware architecture, network infrastructure, and behaviourist learning mechanisms.

## C. Planned Learning Resources and Mini Lecture

### Overview of the Plan

The project covers five modules: AI Hardware, Networks and Infrastructure, Behaviourist AI and Reinforcement Learning, Sensors and Intelligent Systems, and Integration and Optimization. All learning resources are built from one shared source of content, so terminology, examples, and visuals stay consistent across the Study Guide, the slides, and the video tutorials.

### Component Plans

| Component | Initial plan |
|---|---|
| **Shared Markdown content** | One Markdown file per module, organized as: learning goals → key terms → explanation → worked example → short activity → references. Terms and example names are fixed here first, and every other resource reuses them. Image and diagram references use consistent file names so they can be reused in Stage 2 slide production. |
| **Study Guide and Test Bank** | The Study Guide follows the module order. Each module has a summary, a glossary, and adapted versions of the slide visuals (tables, diagrams, annotated images). Learners study the summary and visuals, practise with a short activity, and check understanding with Test Bank questions (multiple choice, short answer, and a scenario question per module) that carry answer explanations. |
| **PPT Slides** | A short, focused deck where each slide carries one main idea. Visuals do the explaining and the text stays brief so the speaker adds the detail. Planned visuals: tables for comparisons, diagrams for processes, relationships and structures, annotated images with labels and callouts, and step-by-step worked-example visuals. |
| **Video Tutorials** | Short narrated tutorials on the concepts that benefit most from demonstration: (1) reading the CPU vs GPU vs TPU comparison and the memory hierarchy, (2) tracing a request through the TCP/IP layers and comparing cloud and edge, (3) following the agent-environment loop with a reward example, (4) comparing camera, LiDAR and ultrasonic sensors and how sensor fusion combines them. |
| **Live Mini Lecture** | See [C1](#c1-mini-lecture). |

### Planned Visuals by Module

| Module | Key visuals | Format |
|---|---|---|
| 01 AI Hardware | CPU vs GPU vs TPU comparison; memory hierarchy; Cloud-Based AI Service (5G networks, AI-powered network optimization) | Table, pyramid diagram, annotated image |

### How the Mini Lecture Is Planned Visually

1. **Review the Markdown content first.** Identify the three to five ideas that most need a visual, such as processes, comparisons, and easily confused concepts.
2. **Match each idea to a format.** A process becomes a diagram, a comparison becomes a table, and a method becomes a worked example.
3. **Sequence the slides.** Open with the main idea, build through examples, and close with a summary visual so the lecture has a clear flow.
4. **Set one style guide.** Fix fonts, colours, icons, layout patterns, and key terminology so the slides and Study Guide match.
5. **Check accuracy and readability.** Compare every visual against the source content and confirm the text is legible and the contrast is sufficient.

### Quality Checks Before Handoff

- [ ] Terminology matches the Markdown content and the Study Guide.
- [ ] Every image and file reference opens correctly in the submitted package.
- [ ] Visuals are sized and named for easy use in Stage 2 slide production.
- [ ] Editable source files are kept so Stage 3 revisions can be made quickly.

### C1. Mini Lecture

- **Proposed topic:** Cloud vs. edge computing for AI systems (Module 02), connected to a Tesla integration case study.
- **Focus question:** Why do some AI systems, such as a self-driving car, process data at the edge instead of sending it to the cloud?
- **Why it matters:** Latency and bandwidth limits decide where AI computation can happen. This question links hardware, networks, and sensors, so it shows the whole project in one manageable example.
- **Initial idea for the example and audience activity:** Use the Tesla sensor layout as an annotated image, then ask the audience to decide, for a few scenarios (emergency braking, route planning, software updates), whether the processing should happen at the edge or in the cloud, and to justify the choice using latency and bandwidth.

### C2. Video Tutorials

**Hardware & Memory**

1. **Proposed topic:** Processor Architectures (CPU vs. GPU vs. TPU) and the Memory Hierarchy
2. **Focus question:** Why do different AI workloads require specialized processors, and how does data movement through the memory hierarchy create performance bottlenecks?
3. **Why it matters:** Understanding hardware limitations explains why deep learning models cannot run efficiently on standard CPUs alone and why data transfer speed is often the real bottleneck.
4. **Initial idea for the example and demo:** Use a simple kitchen analogy on a slide, comparing Registers to a chef's hand (tiny, instant), RAM to a kitchen counter (moderate size and speed), and Storage to a pantry (huge, slow). Then show a simple 3-row table comparing CPU (sequential tasks), GPU (parallel tasks), and TPU (AI matrix math).

**Suggested slide flow**

1. Title and learning goals
2. Big picture: how hardware, networks, and behaviourist AI connect
3. AI hardware: CPU, GPU, TPU (comparison table)
4. Networks: cloud vs edge, latency and bandwidth (side-by-side diagram)
5. Behaviourist AI: agent, environment, reward (loop diagram)
6. Sensors and sensor fusion (table and flow diagram)
7. Integration case study: Tesla or Google TPU (annotated image)
8. Summary visual and key takeaways
9. Quick check questions or reflection

### How the Three Learning Resources Support One Another

The Study Guide, the slides, and the video tutorials all draw on the same Markdown content. The slides introduce each idea visually in the live lecture. The video tutorials let learners revisit the same diagrams and worked examples with narration, at their own pace. The Study Guide reuses the slide visuals alongside written explanations and Test Bank questions, so learners can review, practise and check their understanding afterwards. Because all three share terminology and visuals, learners meet each concept in the same form in every resource, and the mini lecture stays focused on one question within the broader project.

### 2. Content Study and Investigation

- **Research phase:** Team members individually study assigned sub-topics (Hardware, Networks, or Behaviourist AI) using course materials and recommended readings.
- **Knowledge sharing:** Before drafting content, members share their findings in the team chat to build a shared baseline of understanding.

### 3. Markdown Development and Verification Pipeline

- **Modular writing:** Content is written directly in modular Markdown files.
- **Review gate:** No Markdown file is integrated into the main branch or used for downstream resources (slides, study guide, videos) until at least one peer reviewer has checked it for technical accuracy, clarity, and formatting consistency.

### 4. GitHub Workflow and Version Control

- **Repository structure:** A single GitHub repository containing the Markdown source files, asset directories for diagrams, and release folders for final exports.
- **Contribution tracking:** Commit history, issues, and project boards in GitHub serve as tangible evidence of individual contributions.

### 5. Communication, Meetings, & Peer Review

- **Communication:** Daily updates in the group chat and one meeting per week.
- **Peer review:** Each deliverable undergoes a structured cross-check where a teammate tests the explanation or practice questions for clarity.
- **Synchronization of corrections:** If an error or conceptual flaw is found in any deliverable, it is first patched at the Shared Markdown level.

### 6. Testing, Rehearsals, and Feedback

- **Test Bank validation:** Practice questions and trace tables are test-solved by team members outside the authoring domain to ensure difficulty balance and clarity.
- **Mini lecture rehearsal:** The team holds a full live rehearsal at least 3 days before the scheduled classroom delivery date, timing the demonstration and collecting peer feedback.

### 7. Internal Deadlines and Risk Management

**Internal deadlines:** All internal task deadlines are set about 2 days before the official deadline.

| Risk | Mitigation |
|---|---|
| Unfamiliar tools or complex concepts | Consult other group members and hold problem-solving meetings. |
| Uneven workloads or delayed tasks | Track the GitHub project board weekly; if a task stalls, backup members assigned in the task list step in to assist. |
| Version conflicts or broken Markdown links | Strict use of feature branches and mandatory pull-request reviews before merging. |
